材料科研工作台面向 REBCO / 超导薄膜研究。输入研究目标后，平台在服务器上组织文献与证据、构建策略树、生成并评审创新方案，最后形成需要人工确认的实验草案。实验由研究人员完成；回填数据后可以继续分析。

## 1. 打开原有项目与会话

在已准备好依赖与网页资源的仓库目录运行：

```bash
./start-materials.command
```

macOS 也可双击该文件。打开 [http://127.0.0.1:4106/](http://127.0.0.1:4106/)。若提示网页资源缺失，先在仓库目录运行 `bun run setup --web`，再启动。

进入原有 OpenScience 首页，打开或创建项目，再进入会话。继续使用原来的输入框、侧栏、设置和模型选择，不需要进入另一页面。材料流程出现在该会话的工具卡片中。模型供应方、凭据和可用模型在原设置中配置，材料任务沿用发起会话时选定的模型，并记录在成果中。

终端保持打开，按一次 **Ctrl+C** 正常停止服务器。关闭网页后，任务仍在后台运行；停止服务器后，未完成任务需要在下次启动后手动继续。启动脚本发现端口已有程序时仅显示提示，不会停止原进程。

## 2. 描述研究目标

用一句日常表达即可，例如：

> 帮我找找提高 REBCO 薄膜载流能力的新方向。

不需要编写专业提示词，也不需要列出工作流。平台根据意图安排文献整理、策略分析和候选方案；“找方向”默认推进到创新候选，明确要求实验方案时再推进到实验草案。也可以说“先帮我查相关论文”，将本次任务停在文献阶段。

如果只说“提高超导性能”，平台会先用少量问题确认研究哪类材料、主要想改善什么。一轮最多追问两个影响当前研究方向的问题；在原输入框继续回答即可。例如：“我做 REBCO，想让它在磁场下通过更大的电流，先看看有哪些方向。”

设备、精确温度、磁场和工艺参数尚未确定时，可以直接说“还没定，先了解方向”。已知材料和研究目标足以开展文献探索时，平台将这些条件记录为待确认，并继续推进，不要求先填完整的实验条件。已有的真实条件可以在澄清时补充，平台不会替你编造。

会话内研究卡显示进度、追问和成果，之后打开同一原会话即可查看。普通概念提问（例如“什么是磁通钉扎”）仍按问答处理，不自动启动科研任务。

研究卡的阶段条下方会持续显示当前工作：正在检索文献、获取全文、生成策略、评审、修复、校验或保存成果。运行面板还会显示角色步骤、已运行时间、最近模型活动、已接收的输出字符数，以及可展开的执行记录。刷新页面或重新打开会话后仍可查看记录。

“服务可连接”表示网页仍能获取任务状态；“最近模型活动”表示模型接口确实返回了新数据。若请求一直没有返回数据，界面会明确显示等待响应，不估算完成百分比或剩余时间。网络中断时会提示实时反馈不可用；它本身不代表服务器上的任务已停止。可随时点击“停止任务”。

## 3. 管理文献与证据

平台通过 OpenAlex、Crossref 检索论文，再自动查找开放全文、下载 PDF 并提取带页码的正文片段。文献卡区分“论文全文”“部分正文”“论文摘要”，显示可用页数、证据片段和获取失败原因。自动下载的 PDF 与页文本缓存在服务器；不能取得全文时保留真实摘要，正文不全时不会标成完整全文。

后续策略与评审会使用相关正文片段，引用可以展开查看上下文，服务器核对引文、片段与页码。全文下载成功不等于已经逐页完成科学审查；自动检索也不保证覆盖全部相关论文。

对于已完成目标澄清、尚未生成策略的课题，可以在本卡片点击“重新获取全文”，完成后继续原研究目标。已有策略的课题需新建研究使用更新的证据，保留旧成果的引用依据。

本地启动脚本默认使用 AliDNS 的 HTTPS 解析，以适配当前电脑的代理网络。若检索失败，卡片会区分 DNS 解析超时、来源限流、访问被拒绝等原因；修复网络后点击“重试 / 继续”，无需重建课题。需要使用其他解析方式时，可通过 `OPENSCIENCE_DNS_RESOLVER` 选择 `system` 或 `cloudflare`。

在会话研究卡的“文献与证据”中，可以粘贴摘要或正文，也可以上传带文本层的 PDF、TXT、Markdown。新上传的文件会同时保存原件与提取文本，单个原件上限为 20 MB；自动下载的 PDF 也会归档到课题文件夹。旧版只保存了提取文本的手动上传无法凭空恢复原件。当前不提供扫描件 OCR，扫描 PDF 请先转换为可核查的文本。

添加文献时，课题必须处于非运行状态，而且尚未生成策略成果。若任务正在执行，先取消；若已有策略成果，使用新证据需要创建新课题，避免旧策略继续引用已经改变的证据。

每个课题最多保存 24 份资料，单份正文最多 20 万字符，总正文最多 100 万字符；模型读取的上下文还会限长并标记截断。研究笔记可以保存，但不能作为论文原文证据使用。没有可引用的真实文献时，阶段会暂停在失败状态，上传资料后点击继续。

## 4. 从策略到创新方案

### 按阶段配置文献 Skill

在原有 **设置 → Skills → 材料科研阶段** 中，分别为六个阶段勾选需要的文献 Skill，点击保存。默认文献阶段启用 arxiv、openalex、semantic-scholar、research-lit；其他阶段不额外检索，可按需要启用。例如在创新阶段启用 semantic-scholar 进行补充检索，在实验方案阶段启用 arxiv 查找相关方法。取消某阶段全部勾选后，该阶段沿用原有流程。保存配置不会启动、重跑或批准研究，配置在下一次阶段启动时读取，正在执行的阶段保留启动时的配置快照。

这六个 Skill 是文献能力，不会代替策略生成、独立评审、实验设计或数据分析本身。服务器实际加载迁移后的 `SKILL.md`，让当前课题所选模型调用检索、单篇定位、PDF 获取和证据读取工具；研究卡的执行记录显示所用 Skill 及工具步骤。阶段成果的结构化数据记录配置版本、Skill 内容哈希、调用状态和模型用量，便于追溯。

- **arxiv**：预印本检索与开放 PDF。
- **openalex**：跨学科论文、原始摘要和开放全文位置。
- **semantic-scholar**：论文、引用元数据与开放 PDF。原凭据设置中的 Literature access 可配置可选 API Key。
- **research-lit**：组合公开学术来源，合并重复论文和全文候选位置；旧项目的 Zotero、Obsidian 桌面集成不自动运行。
- **exa-search**：查找论文网页及机构仓储副本；先在原凭据设置中配置 Exa API Key。
- **deepxiv**：检索及单篇元数据定位；先在原凭据设置中配置 DeepXiv Token。当前阅读使用平台取得的 PDF 正文片段，未接入 DeepXiv 专有 section API，也不自动注册账号。

Exa 与 DeepXiv 的凭据使用现有加密凭据库，不写入阶段配置或成果。没有凭据时会显示原因，其他来源仍可执行。服务器也可通过 `EXA_API_KEY`、`DEEPXIV_API_KEY`（兼容 `DEEPXIV_TOKEN`）提供相应凭据。

工具只接纳实际来源返回的论文身份、摘要和 PDF，不把搜索摘要、DeepXiv brief 或模型生成内容当作全文。没有 DOI 的机构 PDF 使用来源提供的原件地址，并核对提取文本中的标题；获取失败仍保留摘要与原因。全文原件、正文和页码沿用现有文件与证据归档。

后续阶段补充全文时保存新的证据版本，旧成果引用的文本不变。创新方案可引用补充证据，但仍必须提供所引用策略原有来源的依据。来源访问限制、扫描件或机构权限仍可能影响全文获取率。

每阶段 Skill 补全最多执行 12 轮模型交互、32 次工具调用，达到工作量上限时保留已核验资料并记录提示；模型调用仍没有本地时间上限。原有文献数量和文本容量限制继续生效。

### 策略与方案生成

“策略树”展示调控记录、局限、策略之间的延伸关系及引用原文。核查策略时，重点查看引用是否支持相应结论、实验条件是否可比，以及哪些结论属于推断。

“创新方案”包含假设、设计、机制、可行性、风险与评审。平台执行候选生成、独立评审、相似性与排序、候选演化和最终评审。评审通过仅表示适合进入下一步设计，不代表已经获得实验验证。

推进到实验方案时，工作流等待人工选择。以“找方向”开始的课题完成后，也可以在同一研究卡中选择通过最终评审的候选，点击“根据选中方案设计实验”继续；已有文献与策略会保留，不需要重新建立课题。选择后才生成草案，不会自动批准实验。

只能选择通过最终评审的候选；如果没有候选通过评审，平台保留结果。目标为实验方案的任务会提示重试；探索任务可据此收窄目标后创建新课题。

## 5. 修改并确认实验方案

实验草案包含分组、重复次数、操作步骤、参数依据、表征方法、评价指标与待确认事项。请根据实际设备和实验室要求核查。

确认前可以输入修改要求，例如：

> 保留基线组，新增一个不添加钉扎相的对照组；测试温度固定为 77 K。文献没有支持的生长温度不要给出确定值，请列为待确认。

平台生成新版本，旧版本继续保留。必须确认最新版本才能回填实验数据；已经确认的实验方案不会被原地覆盖。后续实验批次和分析会记录它们关联的确切方案版本。

## 6. 回填实验数据

在会话研究卡的“实验数据与分析”中下载 CSV 模板。下例中的 `groupID` 必须换成已确认方案中的实际组 ID；示例数值只说明格式：

```csv
sampleID,groupID,property,value,unit,temperatureK,fieldT,angleDeg,process,notes
sample-001,control,Jc,2.1,MA/cm2,77,1,0,PLD,首次测量
sample-002,control,Jc,2.3,MA/cm2,77,1,0,PLD,独立样品
```

- `sampleID`：样品编号。重复测量使用相同编号。
- `groupID`：已确认实验方案中的组 ID。
- `property,value,unit`：测量性质、纯数字值和单位，分别填写。
- `temperatureK,fieldT,angleDeg`：温度 K、磁场 T 和角度。缺失值留空，不会自动当作零。
- `process,notes`：工艺记录与备注，可留空。

Jc / 临界电流密度必须记录温度和磁场，零场实验明确填写 `0`。每批最多 5000 条记录，CSV 文本最多 200 万字符，整体请求不超过 3 MiB。上传时输入批次名称，核对后保存，再启动分析。

统计按方案、性质、原始单位、温度、磁场、角度和组别分别计算，不自动转换单位，也不跨条件合并。页面展示测量记录数、独立样品数、均值和样本标准差；同一样品的重复测量不能增加独立样品数。模型基于这些统计提出解释、局限和下一步建议。

新增实验批次后可以再次分析，旧分析结果保留。每次分析绑定当时的方案与批次，便于追溯。

## 7. 失败、取消与导出

材料工作流的模型调用没有本地时间上限，会持续等待模型完成，长时间推理或暂时没有数据也不会触发平台的连接、空闲或总时限。第三方接口或网络自身仍可能返回超时、断连等错误，已完成的成果会保留。格式或引用校验失败时只尝试一轮修复，不会无限重试。恢复或重试可能产生新的模型费用。

取消会停止当前执行请求，同时保留已经完成的成果。服务器异常退出后，任务标为中断，需人工确认再恢复。当前最多并行执行两个课题，其他课题排队。

课题可以导出完整 JSON，包括目标、文献、成果版本、实验批次与事件。默认数据目录为 `~/.openscience/materials/`；如更改过 OpenScience 数据位置，以实际数据目录为准。备份整个数据库前先正常停止服务；运行中备份必须采用 SQLite 一致性快照，不能只拷贝主数据库文件。当前 JSON 导出用于留档，没有完整课题导入入口。

## 8. 在原项目中查找文件和成果

研究卡内显示“文件与成果”的保存位置、同步状态和操作入口。点击打开文件夹，会定位到原有“文件”面板；点击查看成果，会打开原有“成果”列表。也可以从卡片中的文件条目直接预览论文、数据或报告。

新课题自动按原会话的工作目录归档到 `materials/<课题编号>/`：选定可读写来源文件夹作为工作目录时，产物保存到该文件夹下；使用独立会话工作区或只连接只读来源时，产物保存到该会话的受管工作目录。卡片显示实际绝对路径，不能仅凭“连接了来源文件夹”判断保存位置。课题首次归档后固定位置，之后切换工作目录不会自动搬动历史文件。

- `papers/`：文献文本、元数据，以及实际获取到的 PDF 或上传原件。只有摘要时保留摘要，不生成不存在的全文。
- `data/`：实验批次的结构化数据与 CSV，保留其关联的方案版本。
- `reports/`：目标、文献、策略、创新方案、实验方案和分析报告，包括 Markdown 与 JSON 的历史版本。
- 课题索引与快照：便于从文件中查看课题内容和关联关系。

各阶段报告同时进入原“成果”，可查看和下载保存版本。文件镜像是便于查阅和开发的副本；科研流程仍以材料数据库中的已校验版本为依据，手动编辑报告文件不会改写已经确认的实验方案。同步发现文件被人工修改时会保留该文件并提示冲突。

成果列表将同一课题、同一阶段的报告与配套结构化数据放在一张卡片中，显示阶段标题、课题名和正文摘要。点击卡片查看报告，点击“数据”打开 JSON；更多菜单可分别下载、重命名或移入回收站。两个文件各自保留原有版本，搜索报告或数据的名称都能找到该成果。单独的数据文件和其他类型成果仍可独立查看。

完整备份需要保存 OpenScience 数据目录（包含材料数据库、原件缓存、会话信息和成果库），以及卡片显示的外部工作目录。仅复制课题文件夹不包含全部运行状态，仅复制材料数据库也不包含原成果库。

旧课题点击“同步已有资料与成果”即可归档已有资料，无需重新运行模型。同步不会补做全文检索或恢复旧版未保存的原始附件。无法确认原会话归属、目录权限失效或磁盘写入失败时会显示原因，修复后可以重试同步，已完成科研成果仍保留。

## 9. 使用范围

当前版本为单工作空间，尚未实现每用户独立空间、租户权限或设备控制。不同课题用于组织科研内容，不构成用户隔离。使用第三方模型 API 时，相应研究内容会发送给该模型供应方。

SupraMAS 的科研方法已迁入平台执行流程。网页任务直接调用服务器的 OpenScience Provider 与文献连接器，不需要另外运行旧的 Codex CLI 脚本。Linux 服务器部署与后续扩展见仓库的 `docs/notes/materials-workbench.md`；当前先在本电脑验证完整科研闭环。
