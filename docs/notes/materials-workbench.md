# 材料科研工作台：本地运行与迁移说明

本工作台以 OpenScience 的网页、模型接入和服务器为基础，迁入 SupraMAS 的材料科研方法与结构化成果契约。首版聚焦 REBCO / 超导薄膜：用户通过自然语言提出目标，服务器执行目标澄清、文献整理、策略树、创新方案与实验草案；研究人员确认方案、完成实验并回填数据后，平台生成分析与下一轮建议。

材料能力集成在原有 OpenScience 首页、项目与会话中，不提供另一套独立工作台页面。用户继续使用原输入框、模型选择和会话记录；研究任务通过会话内的材料工具卡展示进度、成果与操作。

当前交付为单机、单工作空间应用。先在本电脑验证真实科研流程，再迁移到 Linux 服务器；本次没有部署远程服务器。

## 本电脑启动

在仓库目录执行：

```bash
./start-materials.command
```

也可以在 macOS Finder 中双击该脚本。它定位自身所在的仓库，优先使用 PATH 中的 Bun，再查找 `$HOME/.bun/bin/bun`。项目固定 Bun 版本以 `package.json` 的 `packageManager` 为准，当前为 1.3.14。

访问 [材料科研工作台](http://127.0.0.1:4106/)。启动脚本运行的是嵌入了网页资源的 OpenScience 后端，网页和 API 使用同一个端口，不需要另开 Vite。脚本不会修改模型配置或停止已有进程；检测到 4106 已占用时仅显示提示并退出。

本机代理使用虚拟 IP DNS，且 Cloudflare 的 DNS 引导地址在当前网络不可达。启动脚本默认设置 `OPENSCIENCE_DNS_RESOLVER=alidns`，通过 AliDNS 的 HTTPS 接口获取真实地址，仍保留出站域名、公网地址与 TLS 证书校验。使用系统 DNS 的环境可运行 `OPENSCIENCE_DNS_RESOLVER=system ./start-materials.command`；能访问 Cloudflare 的环境也可显式选择 `cloudflare`。DNS 解析超时、来源限流及响应格式错误会分别提示。文献供应方可能限流；某个来源不可用时会尝试其他来源，也可以上传原文补充。

首次准备环境，或修改前端后更新嵌入资源：

```bash
bun run setup --web
```

脚本发现 `backend/cli/src/web/assets.generated.ts` 不存在时会提示执行上述命令。修改源码后，旧的嵌入网页不会自动更新，需要重新构建。后端源代码变化也需要自行正常停止旧进程，再启动新进程。

服务在终端前台运行。按一次 **Ctrl+C** 正常停止，等待退出后再关闭终端。关闭网页不停止任务；停止服务器会中断尚未完成的阶段，下一次启动后需要在原会话的研究卡中明确点击继续。原先的 `stop-local.command` 面向另一套本地启动约定，不是本脚本的进程管理入口。

## 模型与科研执行

使用原有设置与输入框中的模型选择，沿用 OpenScience 全局 Provider 配置。会话 Agent 创建材料任务时，将当前选定的模型传给工作流。启动脚本没有内置 API 地址或密钥。模型请求由服务器发出，密钥不会作为课题成果发送到网页或写进导出文件。使用第三方模型 API 时，提示词中的研究目标、证据和实验数据会发送到该供应方；服务器承担任务调度、文献处理与统计，模型推理发生在供应方。

当前实现直接调用 OpenScience Provider API，复用文献 connectors。SupraMAS 的科学契约、调控维度、证据要求与多角色流程已经迁入本仓库，原项目的 Codex CLI / SDK 脚本不再是平台任务执行入口，也不要求使用者在浏览器之外启动这些脚本。

创新阶段正常包含五次独立模型调用：候选生成、初次评审、相似性分析与排序、候选演化、最终独立评审；相似性与排序由同一轮承担，合计覆盖六类职责。这里是职责分离的模型调用，不代表六套独立训练的模型。策略构建与实验方案各包含生成、独立评审。所有结果继续通过结构、引用原文和关联关系校验。

材料工作流的模型请求不设置本地总时限、连接等待或流空闲时限，持续等待模型完成；`OPENSCIENCE_MATERIALS_MODEL_TIMEOUT_MS` 已移除，不再生效。模型调用通过请求上下文关闭 Provider 的这些计时器，不改变普通会话的超时配置，仍沿用所选模型的参数（包括推理强度）。用户取消和服务停止仍会中止当前请求；第三方接口或网络自身的错误及超时仍可能结束请求，已完成的成果会保留。SDK 自动重试关闭；结构或证据校验失败时，该调用允许一轮修复。失败会记录为失败状态，不无限重试，也不把模拟输出伪装成完成结果。用户主动重试会产生新的模型调用和费用。每份成果保留实际调用的模型、角色及供应方返回的 token 用量。文献检索、PDF 下载和解析继续使用各自的超时设置。

## 从自然语言到实验反馈

研究卡的阶段条下方提供实时运行面板，无需切换到另一个页面：显示当前科研阶段、角色职责及计划步骤、模型、已运行时间、最近模型活动和已收到的输出字符数。文献阶段显示正在检索的来源与检索词，以及全文处理的实际条数。模型请求发出后若没有返回数据，仅标记为等待响应；收到推理活动和正文输出后再更新相应状态，不推测模型内部进展、不展示思维链或未校验的中间成果。格式与引用校验、修复、评审和保存也分别记录。

前端运行时每 2 秒读取轻量活动快照，只有课题业务版本变化时才重新加载文献和成果。服务连接状态与模型最近活动分别显示，连接失败时明确提示实时反馈中断。活动独立保存于材料 SQLite 数据库，最近 200 条记录可展开查看，刷新或重新打开会话仍保留；流式活动更新不会增加课题业务版本，也不会让“停止任务”因高频更新而持续冲突。停止、失败或完成后计时停止。旧课题仅展示实际已有记录，不补造历史进展。

1. **原会话输入**：在原首页打开或创建项目、新建会话，在原输入框说出研究想法即可，例如“帮我找找提高 REBCO 薄膜载流能力的新方向”。不要求用户提供专业提示词、工作流名称或完整实验参数。Agent 调用 `materials_workflow` 创建并绑定本会话的研究任务；找方向默认推进到创新候选，明确需要实验方案时才推进到实验草案，用户也可以要求只整理文献。
2. **同会话跟进**：进度与成果显示在原对话中的材料研究卡，刷新原会话后仍可恢复。只有影响当前研究方向的缺失信息才暂停追问，每轮最多两个问题；可以继续在原输入框回答，或使用卡片的回答控件。材料和目标已知时，尚未确定的设备与精确条件记为待确认，不阻止早期文献探索。补充后重新澄清，旧成果版本保留。普通概念问答不自动启动工作流。
3. **文献与证据**：自动检索 OpenAlex、Crossref，再按 DOI 或 arXiv 标识解析开放副本、下载 PDF 并提取带页码的正文片段。没有摘要的检索记录只有在取得真实正文后才加入证据库。服务器缓存自动下载的 PDF 与页文本；失败时保留摘要和明确原因，正文不全时标为“部分正文”。也可以上传文本 PDF、TXT、Markdown，或粘贴摘要/正文。手动上传 PDF 在浏览器提取文本，不执行 OCR；新上传同时将原件保存到服务器并归档到原项目文件中，旧版未保存的原件无法恢复。
4. **策略树**：生成与论文、原文引用关联的调控记录、局限与延伸关系。可查看引用原文、来源及证据缺口。
5. **创新方案**：比较候选、查看评审，只能选择最终通过评审的候选继续。探索任务完成后，仍可在同一卡片中人工选择候选并继续生成实验草案，保留已有文献与策略。全部候选未通过时，成果保留；目标为实验方案的任务将阶段标为失败并允许重试，探索任务可据此收窄目标后创建新课题。
6. **实验方案**：生成分组、步骤、参数依据、表征与风险。确认前可用自然语言提出修改要求，生成新版本；只能确认最新版本。确认后冻结方案版本，等待人工实验。
7. **实验数据**：CSV 批次必须关联已确认方案，实验组 ID 必须存在。手动启动分析后，平台先按条件计算统计，再由模型分析结果与下一步。新增批次可再次分析，旧结果版本保留。

论文原文、模型推断、候选设计和实验测量是不同性质的数据。通过 AI 评审不等于实验验证成功；平台不会代替人完成样品制备、设备操作和安全确认。

## CSV 回填格式

使用界面的模板列名，UTF-8 编码。以下为格式示例，`groupID` 必须替换为当前已确认方案中的实际组 ID；数值是示例，不是科研结论：

```csv
sampleID,groupID,property,value,unit,temperatureK,fieldT,angleDeg,process,notes
sample-001,control,Jc,2.1,MA/cm2,77,1,0,PLD,首次测量
sample-002,control,Jc,2.3,MA/cm2,77,1,0,PLD,独立样品
```

必填列为 `sampleID,groupID,property,value,unit`。数值与单位分列；Jc / 临界电流密度必须同时填写温度 K 和磁场 T，零场测量明确填 `0`。角度缺失保持缺失，不会推断为零。`process` 和 `notes` 可记录工艺条件与备注。

每批最多 5000 条测量记录，CSV 文本最多 200 万字符；HTTP 请求上限为 3 MiB，多字节字符较多时应分批上传。统计按方案、性质、原始单位、温度、磁场、角度和实验组分组，不自动换算单位，也不跨条件合并。标准差按测量记录计算，同一样品的重复测量不能当作独立样品重复。

## 运行架构与数据

| 位置                                         | 职责                                           |
| -------------------------------------------- | ---------------------------------------------- |
| `frontend/workspace/src/materials/`          | 原会话内工具卡、成果、证据、实验方案与数据控件 |
| `tooling/util/src/materials.ts`              | 前后端共用科研数据与请求契约                   |
| `backend/cli/src/materials/domain.ts`        | REBCO 领域规则与阶段提示                       |
| `backend/cli/src/materials/pipeline.ts`      | Provider 调用、角色评审与修复                  |
| `backend/cli/src/materials/literature.ts`    | 文献检索、去重、全文获取调度与容量管理         |
| `backend/cli/src/materials/fulltext.ts`      | 复用全文解析与提取、PDF 缓存、页码与证据分块   |
| `backend/cli/src/materials/validation.ts`    | 证据与科研关联校验                             |
| `backend/cli/src/materials/statistics.ts`    | 按实验条件计算的确定性统计                     |
| `backend/cli/src/materials/store.ts`         | SQLite、版本、事件、执行权                     |
| `backend/cli/src/materials/workflow.ts`      | 阶段推进、审批、取消、恢复、队列               |
| `backend/cli/src/server/routes/materials.ts` | 全局 `/materials` API 与 OpenAPI               |

默认科研数据位于 **`~/.openscience/materials/`**，核心数据库是 `materials.sqlite`。若设置了 `OPENSCIENCE_DATA_DIR` 或通过设置迁移过数据目录，以实际 OpenScience 数据目录下的 `materials/` 为准。模型配置与凭据属于 OpenScience 全局配置，不在仓库内。不要把含真实凭据的全局配置加入 Git。

材料文件与原项目通过持久的原会话 ID 关联。`materials/library.ts` 解析并验证真实 Project / Session，使用 `SessionFilesystem` 的当前工作目录与写入授权，在 `materials/<mat_id>/` 下生成论文、批次和版本报告。第一次同步后固定归档目录，不随工作目录选择自动迁移。来源只读或会话选择 scratch 时使用会话受管目录；卡片始终展示实际路径。文件写入经授权复检和安全文件 IO，已有人工修改不会被自动覆盖。

业务记录提交后异步同步文件和原 `ArtifactStore`；同步失败与研究阶段状态分离。阶段报告使用稳定来源键保存原 Results 版本，按材料成果 ID / 内容校验去重。同步状态与收据独立保存在材料目录，不增加科研业务 revision。`GET /materials/projects/:id/library` 查询位置和索引，`POST` 同一路径以空 JSON 请求重试同步，均不调用模型或重新获取文献。旧课题按已保存 sessionID 恢复归属；不存在或有歧义时拒绝猜测绑定。

新原件上传使用 `POST /materials/projects/:id/sources/upload` 的 multipart 表单，字段为 `file` 与 JSON 字符串 `source`。原件上限 20 MB，整请求上限 23 MiB；普通 JSON 文献、CSV 和决策接口仍为 3 MiB。原件按服务端生成的文献 ID 保存在 `materials/projects/<mat_id>/uploads/`，不把二进制或 base64 写入科研 SQLite。自动 PDF 缓存和手动原件均只复制已经存在且通过校验的文件。

自动下载的 PDF 和页文本保存在数据目录的 `materials/papers/` 下，按课题和来源分开缓存。重试可复用已经提取的内容。正文按页分块，模型按课题关键词及方法、结果、局限等内容选择可见片段；下载完成不等于模型已经逐页审查全文。自动正文的引用必须携带对应片段编号，服务器同时核对原文、来源和页码。

尚未生成策略的课题，可以在原会话“文献与证据”中点击“重新获取全文”，完成后继续原研究目标；旧文献整理报告作为历史版本保留。已生成策略的课题不原地更新证据，需要新建研究使用新来源，避免旧结论的引用失效。

每个课题保留所属原会话、目标、来源、阶段状态、不可变成果版本、批次与事件。`materials_workflow` 工具根据服务端会话上下文绑定归属，并拒绝操作另一会话的任务；这不是多租户安全隔离。决策通过 revision 检查防止旧页面覆盖新状态。单课题不能并行执行；服务器全局 FIFO 队列最多同时运行两个课题。SQLite WAL 与执行权记录防止同机多个进程重复执行同一个数据库中的任务；进程崩溃后，未完成任务标记中断，需人工恢复。取消会中止正在进行的模型/检索请求，已完成成果保留。

默认运行时持有跨进程的数据目录迁移屏障，避免任务仍在使用 WAL 时复制或切换目录。当前服务已打开材料工作台后，应正常停止相关服务器进程，再进行离线迁移。

备份时先正常停止服务。完整备份应包含整个 OpenScience 数据目录（其中有 `materials/`、原会话记录、`artifact-store/` 与受管工作区），以及卡片显示的外部工作目录。仅复制 `materials/` 不包含原成果库和完整会话绑定信息。**不要在服务运行时只复制 `materials.sqlite` 文件**；运行中的备份需要使用 SQLite 一致性快照机制，将主库和 WAL 的状态作为同一逻辑数据库处理。网页的 JSON 导出适合单课题审阅与留档，当前没有与之对应的完整项目导入界面，不能替代数据库备份。

## 当前范围与限制

- 当前只有默认工作空间，没有注册、登录租户、成员权限或容器级用户隔离。OpenScience 全局 API 认证不等于每用户独立空间，不能直接作为开放注册的公共平台。
- 工作流由经过校验的固定阶段组成，AI 识别目标与填充参数；不是任意自生成并执行代码的通用自主实验室。
- 自动文献获取会尝试开放 PDF 副本，不保证获得每篇全文或穷尽文献。保留出站网络策略、公网地址与重定向校验，不绕过付费墙。标题、检索片段、登录网页和元数据不能升级为论文正文。每篇最多尝试 4 个地址，默认总时限 60 秒、单地址 25 秒、PDF 上限 25 MB；两篇并行处理。扫描页或文本截断会明确标注，精确工艺参数需要实际原文支持或人工确认。
- 每课题最多 24 份来源、单份正文 20 万字符、正文合计 100 万字符。模型上下文还会限长并标注截断。扫描 PDF 需先在外部做 OCR 后上传文本。
- 运行时添加来源需先取消任务；生成策略之后不能修改该课题的证据集合，以免旧策略与后续成果失去依据。需使用新文献时创建新课题。已确认实验方案不可原地修改。
- SQLite 是本机持久化方案，不支持将数据库置于网络共享盘作为多节点任务队列。不要为同一个工作空间启动多套彼此独立的数据库并期待它们共享状态或去重执行。
- 未实现实验设备控制、自动制样、实验仪器直连、通用数据分析任务路由、贝叶斯优化、论文自动投稿或多用户计费。当前数据分析从本课题已确认方案和回填批次开始。

## 后续 Linux 部署路径

先在本地用一个 REBCO 课题验证目标、证据、实验方案与真实回填数据。迁往 Linux 时保持当前单节点架构即可，不需要先拆成多个服务。

建议将源码放在 `/opt/materials-platform`、持久数据放在 `/var/lib/materials-platform`、配置放在 `/etc/materials-platform`，由专用系统用户运行。安装 Linux 对应的固定 Bun 版本和依赖，再构建网页：

```bash
cd /opt/materials-platform
bun install --frozen-lockfile
bun run setup --web
```

使用 systemd 管理一个后端进程，将以下命令作为服务启动命令，`bun` 换成服务器实际安装的绝对路径：

```bash
bun --no-env-file run --cwd backend/cli --conditions=browser src/index.ts serve --port 4106
```

设置服务的 `WorkingDirectory=/opt/materials-platform`。通过权限受控的 systemd `EnvironmentFile` 配置 `OPENSCIENCE_DATA_DIR`、`OPENSCIENCE_CONFIG_DIR` 及需要的服务器凭据，不把密钥写入 unit、源码或前端包。首次在服务器配置 Provider，或将本机配置以安全方式迁入；迁移数据前停止本机服务。

后端保持绑定回环地址，在前方配置支持流式响应的 HTTPS 反向代理与访问认证。对外使用前先补充工作空间归属、用户权限、任务与文件授权、执行隔离、配额、备份与审计；将这些能力上线之前，只面向受信任的个人或受控团队。当前仓库只提供上述部署路径说明，没有创建系统用户、安装 systemd 服务或更改远程机器。
